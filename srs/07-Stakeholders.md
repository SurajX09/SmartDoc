# Stakeholders

---

# 1. Overview

Stakeholders are the individuals or groups who are directly or indirectly involved in the SmartDoc project. They contribute to the planning, development, maintenance, or use of the website.

Clearly identifying stakeholders helps define responsibilities, improve communication, and ensure that project objectives are achieved successfully.

---

# 2. Stakeholder List

| Stakeholder | Role | Responsibility |
|-------------|------|----------------|
| Project Owner | Business Owner | Defines business goals, approves requirements, and manages the project. |
| End Users | Website Visitors | Browse the website, explore services, and contact SmartDoc for assistance. |
| UI/UX Designer | Designer | Designs the website layout, user interface, and user experience. |
| Frontend Developer | Developer | Builds the user interface and implements website functionality. |
| Content Manager | Content Creator | Prepares and updates website content, service descriptions, and FAQs. |
| Tester (QA) | Quality Assurance | Verifies that the website functions correctly and provides a smooth user experience. |

---

# 3. Primary Stakeholder

## Project Owner

The Project Owner is responsible for:

- Defining business objectives.
- Approving project requirements.
- Reviewing completed work.
- Managing project direction.
- Ensuring business goals are achieved.

---

# 4. Secondary Stakeholders

## End Users

End users interact with the website to:

- Learn about available services.
- Understand required documents.
- Contact SmartDoc through WhatsApp.
- Navigate the website easily.

---

## UI/UX Designer

Responsible for:

- Designing responsive layouts.
- Creating intuitive user experiences.
- Maintaining visual consistency.
- Improving usability.

---

## Frontend Developer

Responsible for:

- Developing responsive pages.
- Implementing navigation.
- Building reusable components.
- Optimizing website performance.
- Ensuring cross-browser compatibility.

---

## Content Manager

Responsible for:

- Managing website content.
- Updating service information.
- Maintaining FAQs.
- Ensuring content accuracy.

---

## Quality Assurance (QA)

Responsible for:

- Functional testing.
- UI testing.
- Responsive testing.
- Browser compatibility testing.
- Reporting issues before deployment.

---

# 5. Stakeholder Communication

The Project Owner will review project progress regularly.

Design, development, testing, and content updates should remain aligned with the business objectives defined in this SRS.
